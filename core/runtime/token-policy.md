# APEX Context Compiler 与 Token 策略

## 单一上下文索引

`.apex/runs/<run-id>/context-index.json` 记录事实来源、摘要、哈希、所属阶段和失效条件。未变化内容引用摘要与路径，不重复全文加载。

## 按阶段装载

- Intake：需求、项目入口、轨道判定资料。
- Baseline：目标页面、运行入口、API、状态、权限和必要项目文档。
- Visual：Site Contract、页面事实、Functional Freeze及当前需要的素材类别。
- Implement：已确认Visual Bundle、Implementation Map、目标代码与关联消费者。
- Verify：验收契约、改动文件、目标页、关联页面和运行命令。

不得在每轮加载全部代码、全部历史记忆、全部Skill说明或完整素材候选池。在线素材按类别和任务检索，只把入选项与比较摘要写入Bundle。

## 预算与降级边界

- 每个阶段开始前只装载完成该阶段 Gate 所需的最小证据集；新增上下文必须说明其所属阶段、来源和必要性。
- 预算紧张时，先复用 `context-index.json`、已确认契约、内容哈希和 Checkpoint；其次缩小当前待解决问题；不得跳过准入、Gate、严格 1:1 校验、真实验收或恢复记录。

## 执行 I/O 快路径

普通状态查询、自动串行阶段与未改变的 Existing 基线重试必须优先读取 `state.json`、`context-index.json`、`operations-index.json` 与 `source-integrity-index.json`，不得因轮询而重扫整个项目或遍历全部 operation receipt。`source-integrity-index.json` 只能以路径、文件指纹和上次已验证 SHA-256 复用不可变代码快照；它不构成 Gate 证据。Gate 1、Gate 2、Gate 3、运行时 Demo 登记和实施授权仍必须重新计算其规定范围的完整 SHA-256，缓存失效、缺失或旧版 receipt 时必须退回权威校验，不能以文件时间戳或索引替代。
- 需要扩大上下文、重跑上游阶段或进行大范围探索时，应先形成明确范围与预期产物；无法在既定预算内保证质量时，Router 应返回 `blocked` 或要求重新定界，而不是输出未经验证的结论。
- 禁止为了压缩 token 而重复粘贴完整历史、无差别扫描整个代码库、并行生成多个无验收路径的方案，或把用户提供的事实替换为推测。

## 输出策略

完整审计写入运行产物；用户默认只看到阶段、关键结论、风险、确认项和下一步。旧规则“每一步必须大段显示”被本策略取代。

专业角色链的内部 advisory 不作为用户逐条阅读的对象。用户只在 Gate 中看到完整、可读的方案与“角色决策摘要”；确认前仍必须按 Invocation Spec 持续流式渲染聊天导读和全部必需章节。

## 专业角色预算

- 角色选择器启用当前阶段、当前变更闭包需要的**全部**职业角色；不得以默认数量上限静默省略产品、后端、前端、设计或 QA。互不依赖的专项角色最大并发为 2；超出并发上限时排队，不丢弃。账本在同一个 Run 的任务领取事务中执行该上限；领取返回 `waiting` 时不得启动该 Agent。过期租约先经恢复并完成隔离，再释放并发槽位。
- 每个角色只接收当前 Run 的工件摘要、事实引用、哈希和必要闭包；禁止加载完整历史、完整角色库或无关项目文件。
- advisory 缓存键必须包含角色适配版本、输入工件 SHA-256、轨道和变更范围；任一依赖变化即失效。每个选择都必须创建一个持久 Agent Job；重试复用同一 Job，不能重建 Job 或重复记账。
- 每个 advisory 必须上报输入与输出 token。账本按阶段和 Agent 双维度累计；超过阶段或 Agent 预算，当前 Job 失败并保留可诊断原因，不能以缩短内容、跳过角色或伪造完成继续。
- 预算不足时优先缩小未确认的当前问题、复用当前 Run 已验证 advisory 或关闭增强角色；不得跳过 Gate、来源验证、运行时证据或专业角色的必要产物。

完整职责与降级规则见 [受控专业角色链治理](agency-role-chain-governance.md)。

## 增量与失效

摘要必须绑定内容哈希。代码、Site Contract、Stitch或用户决策变化时，仅失效依赖该输入的摘要和下游产物。Token不足或任务中断时使用Checkpoint恢复，不重新复述整个框架。


失败、超预算及租约中断的 Agent 尝试必须单独记录用量来源和尝试编号。已知实际用量即使超过预算也如实记账；无法获取时记录 unknown，零值仅作占位。宿主不可对同一尝试同时使用独立 Token 登记与结算用量。账本覆盖不到的宿主调用仍不可宣称硬上限。


新选角色的领取事务按阶段已记录用量与运行任务预留额度计算剩余额度，足额才领取；并发预留导致不足时返回 waiting，实际记录的用量导致不足时返回 budget-exhausted，不自动循环重试。旧作业没有阶段预算字段时保持兼容但不声称完成预留。预算只覆盖宿主实际提供或代理侧记录的用量；宿主不支持请求级上限或用量不完整时，预留是软控制，不是实际硬上限。

用户或项目明确提供总预算时，可在当前阶段授权下调用 `agent-runtime.mjs run-budget <run-dir> <stage> <total> <verification-reserve> [recovery-reserve]`。Run 账本在同一事务中配置额度并记录变更；不预设未经授权的金额。所有阶段的已记录用量和运行中预留共同占用总额。普通任务不能占用尚未使用的验证与恢复预留；验证任务可使用总额度，重试或有同阶段已执行角色记录的修复任务可使用恢复预留，不能自行将首次任务标为恢复绕过限制。预留随相应实际用量和运行中预留递减，避免重复冻结已使用的额度。已发生用量仍如实登记；超额结算拒绝成功并保留记录。旧 Run 未配置总预算时维持原阶段预算行为。

预算状态在角色领取、`agent-runtime.mjs status` 和 `run-metrics.mjs inspect` 中可见。`reportedReserveShortfall` 标识按已登记与估算数值计算的保护额度缺口，即使尚未超过总上限也会显示；`reportedOvercommitted` 和 `reportedAvailable` 同样只是该口径的计算结果。由于宿主全部调用尚未完整计量，实际余额、预留缺口和超额状态保持未知，即使已登记记录均为服务商报告值也不能推断全部用量已覆盖；调度仍按已登记和估算数值执行。并发等待与已记录用量不足分别返回不同原因。Run 预算和预留不能阻止宿主未接入的模型调用，也不能证明未报告的 Token 为零；恢复预留覆盖账本中可识别的角色重试和重选，不能覆盖未登记的外部恢复调用。

普通 Agent 结算和角色意见发布均需核对本次已报告用量与预留、阶段额度。已发生的超额用量仍须入账；超额任务进入待处理状态，不得登记为成功或自动重试，调整额度后才可受控恢复。无法取得用量时保留未知记录，不将零占位解释为实际零消耗。

非 Agent Job 的独立宿主调用如果已取得用量，应通过受控 `agent-runtime.mjs tokens-observed <run-dir> <stage> <observation-key> <input> <output> <provider-reported|estimated|unknown> [limit|null]` 入账。调用方为每次实际调用提供稳定且唯一的 observation key；相同记录重放不会重复计费，内容冲突会报错。已发生用量即使与运行中预留额度合计超过限制也必须入账，返回的 `overcommitted` 提示超额，新 Job 的领取继续按已用与预留额度计算。`unknown` 使用零占位但不表示实际零消耗。该入口仅记录独立宿主调用，Agent Job 的尝试仍通过其结算路径入账；宿主必须避免将同一次调用两次上报，系统无法自行证明两条不同标识是否对应同一次调用。

阶段内存在未知或未核实的记录时，独立用量登记返回 `incompleteUsage: true`，不把剩余额度当作已知值；只有已知用量与预留已超过限制时，才能确定 `overcommitted: true`。未记录的宿主调用仍不在统计范围内，估算值也不是服务商实际值。

领取成功、幂等恢复领取，以及因预算不足或预留等待而返回时，均标记阶段内已知的用量不完整情况；此时 `available` 为未知，`reportedAvailable` 仅表示按已记录数值计算的余额，不能视为实际剩余额度。成功领取回执也包含已记录用量、当前预留和阶段预算；已知记录与预留超额时标记 `overcommitted: true`。未记录的宿主调用无法由账本自动发现，所有领取结果仍仅覆盖已报告用量。


视觉阶段的必选 `taste-skill` 内容计入 UI Designer 的输入预算估算；其他角色使用各自预算，不因设计师加载该 Skill 自动分配同等额度。 若选择角色后 Skill 内容变化，已运行的角色先等待或按租约恢复；没有运行任务时归档并修复旧选择，再以当前 Skill 内容重新选择，不重复启动旧任务。 Skill 缺失时保留旧选择并报告依赖失败；恢复后以实际 Skill 路径和内容哈希识别新输入，再受控重试，不把原失败无限重复。估算按字节计算，仅用于容量规划，不等同于模型实际分词或真实用量；可用时仍以宿主报告的用量为准。已运行的旧任务维持原租约与预留，结束后再迁移未完成的角色预算。


可使用 `node scripts/run-metrics.mjs inspect <run-dir>` 只读检查当前 Run，或使用 `compare <before-run-dir> <after-run-dir>` 对照。报告按来源分别显示服务商报告值、估算值和未核实值，并按 Agent 与可关联的任务尝试列出记录；未知用量显示为未知而不是零，尚未采集的宿主用量不纳入总量。任务满足基本对照条件后，还须单独检查 Token 覆盖：有未知或未核实用量、两次来源记录数不同，或无法确认完整宿主用量时，`tokenAssessment` 返回不可比较，正式差值留空；`partialRecordedDeltas` 仅供检查已记录部分，不能作为整体成本变化结论。当前宿主用量未完整计量，因此不能声称 Token 总成本已改善。耗时包含用户等待，操作时长总和可能因并发重叠；人工介入次数未完整采集时为未知。Gate 3、轨道、范围和能力集合相同也不证明任务、质量与环境可比，仍须核对后才能解释对照结果。

操作回执目录缺失时，操作与失败次数均为未知而非零。当前无法证明回执集合完整，因此失败操作的正式对照差值保持未知；可读取回执的数量差仅作为局部记录供调查，不能用于宣称整体稳定性变化。

受控恢复标记的 `interrupted` 回执是有效记录，须单独计数，不得归类为损坏或当成已失败、已成功；存在中断时对照保持不可比较，直至检查其实际结果及可能的外部副作用。

对照必须使用不同的 Run；同一目录及其符号链接别名不能作为改造前后两次执行。相同的初始账本快照和创建时间会被标记为可能的账本副本并阻止自动对照；初始账本身份缺失或无效时也不能判定可比。此检查不能证明不同账本来自独立任务，任务、质量、环境和数据仍需复核。

Gate 3 时间缺失、无效、早于 Run 起点或晚于读取时刻时，端到端耗时记为未知；不得将未来时间或时钟异常计算为真实耗时。

操作回执无法解析、不是对象或状态无效时计为不可读，并阻止运行间比较；缺失、负数或非数字时长计为未知，不计入已知时长总和。没有任何有效时长时，总和为未知而不是零。

运行状态与用量从账本的同一只读快照读取；磁盘状态投影缺失、不可读或与账本不一致时，报告差异并暂停运行间比较，须先通过受控恢复核查。

报告按 Agent、独立宿主调用和无法归属的旧记录分别汇总已登记用量；对照中的 Agent 差值只覆盖可归属 Agent 的记录，独立宿主调用单独列示。各项仍可能混合服务商报告值与估算值，且都不代表完整宿主用量。

对照前还须核验交付合同与账本中当前有效登记的哈希一致。合同缺失、未登记、变更或不可读取时，能力集合不能用于判断可比性；即使哈希有效，仍须人工判断任务、质量和环境是否可比。
