# APEX 审计规格

## 目的

定义 APEX 在发布前、迁移前、以及重大改造前应执行的统一系统审计口径。

本文件不是某个具体脚本，而是未来 `apex audit` 或等价检查器必须遵守的规则真相源。

## 适用场景

- 对外迁移前
- 对外发布前
- 引入新 skill / 新插件 / 新 connector 后
- 怀疑出现双真相源、平行规则或缺失文件时

## 审计主轴

### 1. 结构完整性

检查：

- `manifest.yaml` 中的入口是否真实存在
- `INDEX.md` 是否能回指所有核心模块
- `core / references / skills / connectors / adapters` 是否齐全

### 2. 真相源一致性

检查：

- 是否存在第二份 APEX 主框架
- 项目投影文档是否错误复制了通用主流程
- skill 清单与来源清单是否一致
- connector / adapter 清单与真实文件是否一致

### 3. 准入与执行完整性

检查：

- 调用协议是否存在
- 准入规则是否存在
- 优先级模型是否存在
- 状态机、确认门、恢复协议是否存在
- 验证模板是否存在

### 4. 开源可用性

检查：

- 来源清单是否具备 `oss_readiness`
- 必备能力中是否存在 `oss-blocked`
- 宿主插件能力是否被错误当成硬依赖

### 5. 发布边界

检查：

- 是否默认只打包自有规则与 adopted 规则
- 是否错误内嵌第三方受限原文
- 是否存在对外不可迁移的宿主依赖却未标注

## 审计输出格式

至少输出：

```text
审计范围：
结构完整性：
真相源一致性：
准入与执行完整性：
开源可用性：
发布边界：
阻断项：
建议项：
最终判定：
```

## 判定等级

- `pass`：当前可作为内部发布级系统包
- `pass-with-risks`：主体可用，但存在明确尾差
- `blocked`：存在阻断项，不应宣称发布级完成

## 当前最小阻断项

满足以下任一情况，应直接判为 `blocked`：

- 缺少调用协议
- 缺少准入规则
- 缺少状态机或确认门
- 缺少 adapter 映射
- 必备能力存在 `oss-blocked`
- 出现双主真相源
