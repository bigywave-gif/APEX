# 系统要求

## 最小系统要求

- 可读取项目代码
- 可编辑项目文件
- 可访问项目文档
- 可执行结构化步骤输出
- Node.js 18或更高版本，用于运行状态控制器与Gate校验器
- Git，用于正式代码识别、Existing 基线、worktree 与回归边界
- npm，用于明确安装宿主 Skill，以及 Gate 2 后按锁定版本物化项目运行时依赖
- 目标项目允许创建 `.apex/runs/` 运行目录
- 当前用户的 Codex 主目录可写，用于安装 Core 与同步全局 Bridge

## 推荐系统要求

- 可重启目标服务
- 可访问真实页面
- 可做截图或浏览器自动化
- 可运行最小验证命令
- 已安装 Playwright Skill 或等价浏览器桥接，用于进入 Visual/Gate 3 的任务
- 可访问 npm、官方资源和已确认的素材来源；离线任务必须已有完整锁定缓存

## 发布维护依赖（非普通运行依赖）

- Python 3，用于公共 PDF 生成
- `reportlab`、`pypdf`、`Pillow`，用于 PDF 生成与检查
- Poppler 的 `pdftoppm`，用于 PDF 渲染验证
- Ruby（含 YAML 标准库），用于当前发布清单解析

普通 APEX 项目运行不应因为缺少 PDF 发布维护依赖而伪装成已具备发布能力；公共 Release 审计必须真实安装并验证这些工具。

## 非功能要求

- 支持长任务分阶段执行
- 支持中断恢复
- 支持少量受控并行
- 支持技能层路由
- 支持增强层能力池的提示式增量更新

## 持续更新边界要求

系统如果支持 APEX 持续更新能力，还必须满足：

- 可区分核心工作流层与增强层
- 可对候选来源做 `最新 / 最优 / 许可 / 适配度` 四类判断
- 可在使用中提示用户是否更新
- 可在用户未确认时保持当前能力池与核心流程不变
- 可在更新后保留回退边界与审计记录
- 可将外部更新检查作为后台旁路任务执行
- 可保证后台更新检查不阻塞主工作流
