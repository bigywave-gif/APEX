# 工具矩阵

## 目的

定义 APEX 在不同阶段需要哪些工具能力。

## 必备工具能力

- 代码读取
- 文件编辑
- 文档检索
- 静态验证

## 推荐工具能力

- 浏览器控制
- 页面截图
- 控制台报错检查
- 运行时重启
- 组件文档化与状态展示
- 无障碍自动检测
- 设计 brief / 视觉提案增强插件

## 阶段映射

### Audit

- 必备：代码读取、文档检索
- 推荐：浏览器控制、截图、无障碍自动检测、设计 brief / 审计增强插件
- Existing 强制证据：真实路由、至少一个页面截图、代码入口、API 请求/响应样本、保护边界和影响图；缺少时不可进入 Visual。

### Plan

- 必备：文档检索

### Visual

- 必备：截图、页面对照
- 推荐：浏览器控制、组件文档化与状态展示、视觉提案 / image-to-code 增强插件
- 可选生成器：Google Stitch。新 Run 中，用户先确认视觉方案和交互式 Demo，再选择是否使用 Stitch；未选择时直接进入内部实施准备与前端落地。选择 Stitch 时，以已确认 Demo 截图和交互为基线，记录参考图与 Prompt 哈希；连接器没有图片输入能力时，通过浏览器控制导入 Stitch UI。浏览器不可用时明确报告缺口，不得要求用户重复上传或静默降为纯文本。`DESIGN.md` 可用于跨页设计约束，不是上传或生成的强制前置；Stitch 结果须对照已确认 Demo，确认范围外的设计变化须由用户决定。Site Contract、实施映射和 Gate 2 随后按所选路线完成。旧 Run 保持原确认模型。
- 在线素材：从 `registry/assets/online-sources.yaml` 的完整候选池按当前任务动态择优，并在 Visual Bundle 中记录候选比较、稳定资源 ID、完整依赖、版本、调用方式、许可证和运行时适配方式；注册顺序不得被当成强制选型。

### Implement

- 必备：文件编辑、静态验证
- 推荐：运行时重启
- 素材实现：只允许消费 Gate 2 已确认的在线素材引用；若来源失效必须按注册表 fallback 重新解析并重新过视觉验收，不得静默换成“相似素材”。

### Verify

- 必备：运行时验证、截图、交互检查
- 推荐：无障碍自动检测、组件状态验证
- Delivery Contract 驱动：只运行本次契约要求的单元、接口、契约、E2E、视觉、无障碍、性能、回归或 smoke 证据；任何要求的类别缺失都必须使 Gate 3 失败。

## 工具降级策略

- 如果浏览器控制不可用，必须明确说明缺口
- 如果截图不可用，必须寻找同等强度的页面验证方式
- 如果 `Product Design` 类插件不可用，新 Run 使用已安装的 `taste-skill`、本地 adopted design rules 和按场景适用的其他技能，保留设计契约与验证；必选技能无法加载时记录原因并修复。旧 Run 保持原确认模型的技能要求。
- 如果 Stitch MCP / SDK 或浏览器导入不可用，保留已确认 Demo 和当前进度，明确报告受影响能力；不得静默替换路线、要求用户重复上传或省略输出映射与 Gate 2。
- 不允许因为某个工具不可用就跳过真实验收
