# APEX 准入规则

## 默认命中语义

- 前端改造
- 视觉升级
- UI / UX 优化
- 页面结构调整
- 布局整改
- 可用性优化
- 响应式修正
- 组件统一
- 页面可见字段、按钮、状态、权限或反馈信息的新增、修复和统一
- 截图还原、页面审计、视觉评审、交互 / 动效与无障碍优化

## 命中后要求

- 必须调用当前 manifest 声明的 APEX Core；不得以旧版、简化版或口头流程替代
- 必须输出入口声明
- 必须判断 `Lite / Standard / Full`
- 必须通过 APEX Router 在目标项目 `.apex/runs/<run-id>/` 创建运行态，并以当前 APEX Core 的 Gate、审批回执与 `implementationAllowed` 作为实现权限真相源

## 全局会话约束

- 本规则适用于所有项目、所有新建、继续和恢复中的 Codex session，并由 `runtime/host-bridges/codex-skill/SKILL.md` 的提示词元数据与 `runtime/codex-discovery.md` 的宿主路由共同执行。
- 用户不必显式提到 APEX；自然语言中任何等价的页面、前端、界面、UI、UX、视觉、设计、布局、组件、样式、表单、按钮、状态、页面权限、响应式、无障碍、交互、动画、截图或审计目标，都必须触发准入判断。
- 不得以“仅调整样式”“小范围 UI 修复”“只改一个字段 / 按钮”“只是看一下”或“未显式提到 APEX”为由跳过当前 APEX Core；命中语义即构成调用条件，范围大小仅影响分级。

新 Codex session 必须创建新的 project-local run；只有同一 session 可以恢复自身已绑定的 run，禁止自动跨 session 续接。
- 纯后端、纯数据、纯服务端接口或纯文档任务在没有用户可见页面目标时不触发；一旦包含页面展示、页面状态或用户交互结果，必须进入 APEX。
- 已命中时，其他设计、实现或组件 skill 只能作为 APEX 阶段能力，不能代替 APEX 的 Preflight、状态机、Gate 或实现权限。

## 歧义处理

如果用户需求可能同时属于局部修正和整页升级：

- 默认按更保守的 `Standard` 进入
- 必要时只允许问一个最关键澄清问题
